Tursina Labs · Design specification v0.2

Kelola

Linux administration from a phone. Structured, auditable, agentless. The visual system exists to make a tired person confident about what a tap is going to do — and fast enough that they are done before the next alert.

01 Direction

The obvious move for a sysadmin tool is black-and-acid-green terminal cosplay. Rejected — this app's entire premise is that it is not a terminal. The reference instead is a rack-mount instrument panel: deep blue-black ink, a single warm amber that reads as a status LED, and colour used only where it carries meaning. Green appears solely to mean healthy. Red appears solely to mean danger. Nothing is decorative.

Type

Three roles, two families. Space Grotesk for anything a human named — screen titles, host names, unit names. IBM Plex Sans for prose. IBM Plex Mono for anything a machine produced — commands, log lines, timestamps, exit codes. The split is semantic: if the string came from the server, it is monospaced. That rule alone tells the user what is theirs and what is the machine's.

Signature — the risk band

Every actionable surface carries a 4px edge encoding its RiskLevel. Read is grey and silent. Mutate is amber. Destructive uses hazard striping lifted straight from industrial safety marking — the one place the design raises its voice. This is not decoration: it is the spec's core abstraction made visible, and it is consistent from a list row to a confirmation sheet.

Read
Inspect only. Permitted in read-only mode. No confirmation.
Mutate
Changes state. Blocked in read-only mode. Single confirmation.
Destructive
Data loss or lockout possible. Type the hostname to proceed.

02 Brand assets

The mark is a status stack: three rounded bars of unequal length — a unit list — with one struck amber, and an indicator dot. It reads as "something here needs you" at 48px, and it avoids every terminal-prompt cliché in the category.

Errors state what happened and what to do. They never apologise and never say "oops". Empty states invite the next action rather than reporting absence. Any string the server produced is monospaced; any string Kelola wrote is not.

10 Flutter implementation notes

Design elementFlutter
Risk bandContainer with left BoxDecoration border; destructive uses a CustomPainter for the hazard stripe
ColoursThemeExtension<KelolaColors> — never hardcode; risk colours resolve from the RiskLevel enum
Typegoogle_fonts or bundled TTF. Bundle for offline and air-gap.
SparklinesCustomPainter over the ring buffer — no chart package needed for a polyline
Log listListView.builder with itemExtent set — fixed row height keeps 10k lines smooth
Destructive sheetshowModalBottomSheet, isDismissible: false, confirm enabled only on exact hostname match
Incident sheetSame modal component as destructive, but isScrollControlled: true; primary action is the most likely mutate, not "View all"
Global searchSearchAnchor / custom delegate over Drift. Hardware intent: Shortcuts widget mapping Control+KeyK
UndoScaffoldMessenger snackbar, 8s, action calls execute(undoProbe) — never a local-only UI revert
DiffFixed-extent ListView of hunks; do not pull in a full editor/diff package for v1
Widgethome_widget or platform channels; payload is last Drift snapshot only. App launch from widget goes to incident route
Keep-awakeWakelockPlus scoped to follow / transfer / tunnel / terminal routes; released in dispose
Dark only in v1Light theme is deferred. Ops work happens at night; do one theme properly first.
